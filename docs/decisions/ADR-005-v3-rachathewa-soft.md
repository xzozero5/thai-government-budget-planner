# ADR-005 — V3 (อบต. ราชาเทวะ) ลดจาก hard เป็น soft + flag รายกลุ่ม

- **Status**: Accepted — 2569-09-19 (main thread) · รายงานคุณนิวในสรุป Phase 1
- **Links**: 03 §6 V3, 02 §A4, `extract/local_sheets.py::check_v3_raja`, T-107, T-110

## Context (ยืนยันจากไฟล์จริงโดย main thread)
`อบต. ราชาเทวะ - Sheets.xlsx`: sheet รายแผนงาน 11 sheets = `ocr_raw_data` ทุกกลุ่ม (345 แถว, รวม 613,887,402 บาท) แต่ `summary_ocr_raw_data` (36 กลุ่ม, มีคอลัมน์ `page`) รวม 615,172,000 บาท — คือ **ยอดรวมที่พิมพ์อยู่ในเอกสาร PDF** ไม่ได้คำนวณจากแถวรายการ. ส่วนต่างรวม 0.21 % แต่รายกลุ่มไม่ตรง 10 จาก 38 กลุ่ม ทั้งบวกและลบ (เช่น งานบริหารงานคลัง/งบดำเนินงาน −14.3 ล้าน; การศึกษา/งบบุคลากร +3.75 ล้าน) → รายการระดับแถวมี OCR ผิด/ตกหล่น/ลงกลุ่มผิดจากต้นทาง. PDF ต้นฉบับไม่มี text layer → เราตรวจเองไม่ได้โดยไม่ OCR (N4)

## Decision
- V3 = **soft**: รายงานส่วนต่างรายกลุ่มใน validation_report; ไม่ทำให้ build ล้ม. ยังคง hard เฉพาะ "ยอดรวมทั้งไฟล์ต่างจาก summary ไม่เกิน 1 %" (กันไฟล์เสีย/อ่านผิด sheet)
- ทุกแถวมี flag `upstream_ocr` อยู่แล้ว; เพิ่ม flag **`group_total_mismatch`** ให้ทุกแถวในกลุ่ม (plan, work, budget_group) ที่ยอดไม่ตรง summary และเก็บยอดตามเอกสารของกลุ่มไว้ใน validation.json
- ไม่แก้ตัวเลขใด ๆ ให้ตรง (ห้ามเดา); Phase 3: tool result ที่มี flag เหล่านี้ต้องบอกผู้ใช้ว่า "ตัวเลขถอดจาก OCR ของต้นทาง โปรดตรวจหน้า N ของ PDF" และ confidence ของ BOQ ที่อ้างแถวเหล่านี้ต้องไม่เป็น high

## Consequences
- ข้อมูล อปท. ชุดนี้ยังมีค่าด้านคำอธิบาย/ระเบียบที่อ้าง/เลขหน้า แต่ความแม่นของจำนวนเงินต่ำกว่าชุดอื่น — ต้องสื่อสารใน UI (badge) และใน PDF export
- ไม่เข้า `[ASK-HUMAN]` ข้อ 2 (ไม่ได้ทิ้งข้อมูล)
