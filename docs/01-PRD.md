# 01 — PRD: Thai Government Budget Planner (MVP)

สถานะ: **Approved for build** (คุณนิว, 19 ก.ย. 2569) · Owner: Thagoon T. · เวอร์ชัน 1.0

## 1. ปัญหา

คนที่ต้องการตรวจสอบหรือเสนอโครงการภาครัฐ (ประชาชน, สื่อ, สส., ผู้ช่วย สส.) ไม่มีเครื่องมือที่ตอบคำถามพื้นฐานได้เร็ว ๆ ว่า **"โครงการแบบนี้ ควรใช้เงินเท่าไหร่ ซื้ออะไรบ้าง และรัฐเคยจ่ายเท่าไหร่ในอดีต"** ข้อมูลมีอยู่ (PBO, ร่าง พ.ร.บ. งบ, ข้อบัญญัติ อปท., เอกสาร กมธ.) แต่กระจัดกระจายเป็น PDF/Excel หลายพันหน้า และไม่มีใครเชื่อมโยง "ราคาที่รัฐเคยตั้ง/เบิกจ่ายจริง" กับ "ราคาตลาดวันนี้"

## 2. ผู้ใช้เป้าหมาย (MVP)

**Primary**: ประชาชน / สื่อ / สส. และทีมงาน ที่ตรวจสอบงบ — ไม่ใช่ข้าราชการที่ทำคำขอ
- ต้องการ: benchmark ราคา, รายการที่ควรมี, หลักฐานที่ชี้กลับได้, รายงานส่งต่อได้
- ไม่ต้องการ: ระบบล็อกอิน, เก็บข้อมูลส่วนตัว, ต้องติดตั้งอะไร

**Secondary** (ไม่ optimize แต่ต้องไม่พัง): เจ้าหน้าที่ อปท. ที่ร่างโครงการ

## 3. Jobs-to-be-done

1. "ผมมีไอเดีย/ได้ยินว่าหน่วยงาน X จะทำโครงการ Y — ช่วยแตกออกมาว่าต้องมีอะไรบ้าง และราคาที่สมเหตุสมผลคือเท่าไหร่"
2. "รายการนี้ (เช่น เครื่องปรับอากาศ 18,000 BTU) รัฐเคยตั้งงบ/เบิกจ่ายเท่าไหร่ ปีไหน หน่วยงานไหน — ขอดูหลักฐาน"
3. "ราคาตลาดตอนนี้เท่าไหร่ ต่างจากที่รัฐตั้งไว้กี่ %"
4. "เอารายงานทั้งหมดเป็น PDF ไปแนบ/ส่งต่อ"

## 4. Scope

### In scope (MVP)
- ใส่ Anthropic API key ของตัวเอง (เก็บใน memory ของ tab เท่านั้น)
- แชทภาษาไทยกับ AI แบบ **interview-driven**: AI ถามจนครบ (พื้นที่, ขนาด, กลุ่มเป้าหมาย, ระยะเวลา, ข้อจำกัด) ก่อนสรุป
- AI ค้นข้อมูลงบในอดีต (PBO 2558-2568, ร่าง พ.ร.บ. 2570 (ฉบับเต็ม + subset รายจังหวัด), ข้อบัญญัติ อปท. ที่ถอดเป็นตารางแล้ว, เอกสาร กมธ. ที่มี text layer)
- AI ใช้ตัวเลขเศรษฐกิจรายปี (CPI/เงินเฟ้อ, ค่าแรงขั้นต่ำ, ราคาน้ำมัน, GDP) เพื่อปรับราคาข้ามปี
- AI ค้นราคาตลาดปัจจุบันผ่าน web search (Shopee/Lazada/ผู้ขาย) พร้อม URL
- ผลลัพธ์: **Project Proposal** = สรุปโครงการ, วัตถุประสงค์, สเปค, BOQ (รายการ/จำนวน/หน่วย/ราคาต่อหน่วย/รวม/เหตุผล/แหล่งอ้างอิง/ความมั่นใจ), สมมติฐาน, ความเสี่ยง, เปรียบเทียบกับโครงการคล้ายกันในอดีต
- Citation panel: คลิกที่ตัวเลข → เห็นไฟล์ต้นทาง, ชีต/หน้า, แถว, ข้อความที่พบ, path เต็มให้ไปเปิดเอง
- Export PDF (ไทย) รวม appendix แหล่งอ้างอิง
- Save/Load proposal เป็นไฟล์ JSON (ดาวน์โหลด/อัปโหลดเอง — ไม่มี server)
- **ภาพประกอบโครงการ** (เพิ่ม 19 ก.ย.): โครงการใหญ่/สิ่งก่อสร้าง/โครงสร้างพื้นฐาน (เช่น ถนน 4 เลน กรุงเทพ–นครนายก) AI สร้างภาพประกอบเชิงแผนผัง/isometric เป็น **SVG** ให้เห็นภาพ — ไม่ใช้ image-gen provider ภายนอก
- **Trend charts** (เพิ่ม 19 ก.ย.): ข้อมูลเชิงสถิติแสดงเป็นกราฟแนวโน้มย้อนหลัง ≤ 10 ปีแบบกระชับ (ราคาต่อหน่วยของรายการจากงบจริง, ดัชนีราคาวัสดุก่อสร้าง เช่น เหล็ก, CPI) — ไม่ต้องละเอียดมาก
- **UI มีชีวิตชีวา**: flat + modern, โทนสีจากธงชาติไทย, micro-interactions ตอบสนองผู้ใช้ (ดู 06-UI-SPEC)

### Out of scope (MVP)
- OCR PDF ที่เป็นภาพ (ลงทะเบียน metadata ให้ AI รู้ว่ามีเอกสารนั้นอยู่ แต่ไม่อ่านเนื้อหา)
- Backend, database, บัญชีผู้ใช้, การแชร์ลิงก์
- Multi-user collaboration
- Scrape Shopee โดยตรง
- Image generation ด้วย provider ภายนอก (OpenAI/Gemini) — ภาพประกอบเป็น SVG จาก Claude เท่านั้น
- ภาษาอังกฤษ (UI ไทยอย่างเดียว; โค้ดอังกฤษ)

## 5. Success metrics (วัดใน QA phase ด้วย eval set 20 โจทย์ใน `docs/07-TESTING.md`)

| Metric | เป้า |
|---|---|
| Citation precision — ตัวเลขที่อ้างว่ามาจากข้อมูล ตรวจย้อนแล้วถูกต้อง | ≥ 95 % |
| ทุกบรรทัด BOQ มี `basis` (`historical` / `market` / `estimate`) และเหตุผล | 100 % |
| Time-to-first-proposal (จากคำถามแรกถึง proposal ฉบับแรก) | ≤ 5 นาที, ≤ 8 turn |
| Initial page load (ไม่รวมข้อมูลที่โหลดตามต้องการ) | < 3 MB gz, TTI < 3 s บน 4G |
| API cost ต่อ proposal (Sonnet) | ≤ 0.5 USD โดยเฉลี่ย |
| Security: key ไม่ปรากฏใน storage/network log ใด ๆ นอกจาก header ไป api.anthropic.com | 0 พบ |
| PDF export เปิดได้ใน Acrobat/Chrome/Preview ฟอนต์ไทยถูกต้อง สระ/วรรณยุกต์ไม่เพี้ยน | ผ่าน |

## 6. หลักการออกแบบ

1. **Evidence-first** — ถ้าไม่มีหลักฐาน ให้บอกว่าประมาณการ อย่าแกล้งมั่นใจ
2. **Explain every baht** — ทุกบรรทัดมีเหตุผลที่คนธรรมดาอ่านเข้าใจ
3. **Nothing leaves the browser** — ยกเว้น request ไป Anthropic ที่ผู้ใช้เห็นและควบคุมได้
4. **Cheap by default** — โหลดข้อมูลเท่าที่ใช้, ส่ง context ให้ AI เท่าที่จำเป็น

## 7. Risks & mitigations

| ความเสี่ยง | ผลกระทบ | แนวทาง |
|---|---|---|
| ชื่อรายการใน PBO ผสมสถานที่/สเปค ทำให้ match ยาก | ค้นไม่เจอ / เจอผิด | pipeline สกัด `item_key` (ตัดสถานที่), `province`, `qty/unit`, `spec tokens`; ค้นแบบ 2 ชั้น (catalog → detail) |
| DuckDB-WASM range request ใช้ไม่ได้บน host บางเจ้า | โหลดข้อมูลทั้งก้อน | ทดสอบ host ตั้งแต่ phase 2; fallback โหลด shard ทั้งไฟล์ (< 24 MB) |
| AI hallucinate ตัวเลข | ความน่าเชื่อถือพัง | ตัวเลข historical ต้องมาจาก tool result เท่านั้น (validate ใน UI: ทุก citation id ต้องมีใน tool log ของ session) |
| ค่าใช้จ่าย API บาน | ผู้ใช้เลิกใช้ | tool result ≤ 50 แถว, prompt caching สำหรับ system prompt + schema, แสดง token counter |
| Web search ให้ราคาผิดบริบท (ขายส่ง/มือสอง) | BOQ เพี้ยน | ให้ AI ระบุเงื่อนไขราคา + ผู้ใช้กด "ไม่เอาราคานี้" ได้ |
| ข้อมูล econ snapshot ผิด/เก่า | ปรับราคาข้ามปีผิด | ทุกค่ามี `source_url`, `retrieved_at`; UI แสดง; ติดป้าย `[UNVERIFIED]` จนกว่าจะตรวจ |
