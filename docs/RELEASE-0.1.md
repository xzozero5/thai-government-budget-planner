# Thai Government Budget Planner — Release 0.1 (MVP)

เว็บ: https://xzozero5.github.io/thai-government-budget-planner/ · โค้ด: https://github.com/xzozero5/thai-government-budget-planner · สัญญาอนุญาต: Apache-2.0 (ฟอนต์ Sarabun: OFL)
สถานะเอกสารนี้: **ร่าง** — T-604 (eval จริง) รันแล้ว "ผ่านบางส่วน"; จะเป็นฉบับจริงเมื่อ QA checklist ส่วนที่ต้องใช้คนตรวจปิดครบ (ดูหัวข้อ "ยังไม่ยืนยัน")

## ทำอะไรได้
- **ร่างข้อเสนอโครงการ + BOQ จากข้อมูลงบจริง**: ผู้ช่วย (Claude, ใช้ API key ของผู้ใช้เอง) สัมภาษณ์ → ค้นงบที่รัฐเคยตั้ง/เบิกจ่ายจริง → ปรับเงินเฟ้อ → (เลือกได้) ค้นราคาตลาดผ่าน web search ของ Anthropic → ออกข้อเสนอที่ **ทุกตัวเลขมีป้ายที่มา** (จากงบจริง / ราคาตลาด / ประมาณการ) + ระดับความมั่นใจ + คลิกดูแถวงบต้นทางได้ (ไฟล์/แผ่นงาน/เลขแถว)
- **โหมดตรวจสอบ**: ใส่ตัวเลขที่หน่วยงานเสนอ → ได้ข้อสังเกตพร้อมหลักฐานเทียบเคียง
- **ข้อมูล**: 2,993,621 บรรทัดงบ (PBO เบิกจ่ายจริง 2558–2568, ร่าง พ.ร.บ. งบประมาณ 2570, ข้อบัญญัติท้องถิ่น, เอกสารกรรมาธิการ) + ตัวชี้วัดเศรษฐกิจ (CPI, ดัชนีวัสดุก่อสร้าง) — query ในเบราว์เซอร์ด้วย DuckDB-WASM แบบ HTTP range (ไม่มี backend)
- **กราฟ/ภาพ**: sparkline แนวโน้มราคาต่อบรรทัด, การ์ดสถิติ, ภาพผังประกอบที่ AI วาดเป็น SVG (ผ่าน sanitizer เข้ม + ป้าย "ไม่ใช่แบบก่อสร้าง")
- **ส่งออก**: PDF ภาษาไทย (Sarabun ฝังในไฟล์, ตาราง BOQ ข้ามหน้า, ภาคผนวกอ้างอิงพร้อมลิงก์, กราฟแนวโน้ม) และ `.tgbp.json` (เปิดดู/ส่งออกซ้ำที่ `#/load` ได้โดยไม่ต้องมี key)
- **แก้เองได้**: แก้จำนวน/ราคาในตาราง → ยอดรวมคำนวณใหม่ → ให้ผู้ช่วยทบทวน → เก็บเป็นเวอร์ชัน

## ข้อจำกัดที่ผู้ใช้ต้องรู้
- **ข้อมูลส่วนใหญ่เป็น "ยอดต่อรายการงบ" ไม่ใช่ราคาต่อหน่วย** (ราคาต่อหน่วยมี ~3 % ของแถว) — ระบบเตือน/ให้ค่าประมาณจากตัวหารร่วม และติดป้าย "ประมาณการ" เสมอ
- ปีงบ 2562 ของ PBO ไม่ครบ (~79 % ของยอดทั้งปี — ADR-004); ข้อมูล อบต. ราชาเทวะถอดจาก OCR ของต้นทาง (ADR-005); PDF สแกนไม่ถูกอ่าน (ไม่มี OCR — N4)
- ตัวชี้วัดเศรษฐกิจทุกค่ายัง `verified:false`; ไม่มีราคาน้ำมัน/ค่าแรงขั้นต่ำรายปีครบ
- ค่าใช้จ่าย API เป็นของผู้ใช้: **Haiku 4.5 ≈ 0.15–0.55 USD ต่อข้อเสนอ** (วัดจริง 3 ครั้งบนหน้าเว็บ + 5 เคส eval: 0.14–0.22); **Sonnet 5 ≈ 0.40 USD** (วัดจริง 1 เคส); Opus 5 ยังไม่ได้วัดจริง
- โหลดครั้งแรกของ workspace ดึง DuckDB-WASM ~8.6 MB gz + ดัชนีค้นหา (lazy); มือถือใช้แชท/อ่านได้ แต่แก้ตารางเป็น best-effort
- ทุกครั้งที่เว็บ deploy เวอร์ชันใหม่ แท็บที่เปิดค้างควรบันทึก `.tgbp.json` แล้วรีเฟรช

## ผลทดสอบคุณภาพคำตอบกับ API จริง (T-604 / T-308) — **ผ่านบางส่วน จำกัดด้วยงบ**
เกณฑ์ที่วางไว้ (`docs/07-TESTING.md` §4) คือผ่าน 18/20 โจทย์ — **ยังไม่ถึง**: งบ API ที่อนุมัติรันได้ 7 จาก 20 โจทย์ (6 Haiku 4.5 + 1 Sonnet 5, ใช้ 1.35 USD) ผ่านเกณฑ์อัตโนมัติ **2/7** (หลังเพิ่มเกณฑ์ "citation ที่โมเดลอ้างต้องเหลือรอดครบ 100 %"; ก่อนเพิ่มคือ 4/7) ยังไม่มีการให้คะแนนคุณภาพโดยโมเดลผู้ตรวจ (ADR-006 ข้อ 10) — รายละเอียดรายเคส: `docs/eval-report.md`, transcript เต็ม: `web/tests/eval/real-runs/`
- **กลไกกันตัวเลขแต่งทำงานจริง**: ทุกเคสที่โมเดลอ้างแหล่งที่ไม่เคยเห็น (source_id แต่งเอง, URL ตัวอย่าง, ค่า CPI ที่ไม่เคยเรียกดู) ถูกตัดทิ้งและบรรทัดนั้นถูกลดเป็น "ประมาณการ / ความมั่นใจต่ำ" พร้อมคำเตือน — แต่แปลว่า **Haiku ยังอ้างแหล่งที่ไม่มีจริงได้บ่อย** (3 ใน 4 ข้อเสนอของ Haiku; อีก 1 ฉบับถูกตัดเพราะบั๊กฝั่งเราที่แก้แล้ว; ข้อเสนอของ Sonnet 5 ไม่ถูกตัดเลย) ให้ถือคำเตือนในข้อเสนอสำคัญกว่าป้าย
- **ค่า "ราคาต่อหน่วย" ในตารางเทียบเคียงอาจเป็นยอดรวมทั้งบรรทัดงบ** — เคสเครื่องปรับอากาศ 18,000 บีทียู แสดงเทียบเคียง 167,500–190,400 บาท ทั้งที่แถวงบจริงปี 2568 ที่มีราคาต่อหน่วยอยู่ที่ 27,900–33,500 บาท/เครื่อง และราคาที่ผู้ช่วยเสนอ (56,500) สูงกว่านั้นราว 2 เท่า — กดดูแถวต้นทางก่อนเชื่อทุกครั้ง
- ข้อเสนองานก่อสร้างมักเป็น **ราคาเหมาต่อโครงการ** (เทียบจากโครงการคล้ายกัน) ไม่ใช่ BOQ รายวัสดุ/แรงงาน — ใช้ตั้งกรอบงบได้ ยื่นเป็น BOQ จริงไม่ได้
- โหมดตรวจสอบ: ข้อสรุปมีหลักฐานจากงบจริงรองรับ แต่ในรอบทดสอบหลักฐานมาจากหน่วยงานเดียว — เป็นจุดตั้งต้นของการตรวจ ไม่ใช่ข้อยุติ
- พบและแก้แล้วจากรอบนี้ (ดูหัวข้อ "ยังไม่ยืนยัน"): ข้อเสนอถูกปฏิเสธทั้งฉบับเพราะรูปแบบ field ผิดเล็กน้อย, citation ค่า CPI ที่ถูกต้องถูกตัดทิ้ง, การค้นล้มเหลวซ้ำ ๆ จาก "คำค้นกว้างเกินไป" (เสีย 1–6 รอบต่อบทสนทนา), item_key ที่พิมพ์ต่างจาก catalog เล็กน้อยได้ 0 แถวเงียบ ๆ

## ยังไม่ยืนยัน (`[UNVERIFIED]`) ณ วันที่ร่าง
- ผลของการแก้หลัง eval วัดซ้ำกับ API จริงแล้ว **1 เคส** (Total Station, Haiku: เดิมไม่ได้ข้อเสนอ / tool error 6 ครั้ง / 16 tool call → หลังแก้ได้ข้อเสนอในครั้งแรก / error 0 / 6 tool call / 0.13 USD) และยืนยันกับข้อมูล production ด้วย e2e `tool-regressions` (input คำต่อคำจาก transcript) — เคสอื่นที่เคยตก**ยังไม่ได้รันซ้ำ** (งบ)
- PDF ใน viewer จริง 4 ตัว (Acrobat / Preview / Chrome / Edge) และการค้น/คัดลอกข้อความไทยใน PDF (T-503) — ตรวจแล้วเฉพาะ pdf.js
- เบราว์เซอร์อื่นนอกจาก Chromium (Firefox/Safari/มือถือจริง), axe a11y, Lighthouse
- ค่าสีธงชาติเทียบประกาศ พ.ศ. 2560; ราคา API ต่อ token (ยึดหน้า Console ของผู้ใช้)
